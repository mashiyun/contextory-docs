# MVPスコープ

## 目的

少ない操作で画面キャプチャ、音声録音、画面録画を取得し、取得直後にAIで要約・Markdown化して、関連する案件・タスク候補へ自動グルーピングできることを検証する。AIの整理結果は、ユーザーが最低1日1回確認・修正して確定する。

MVPは開発者本人が私用Macで開発・ビルドし、私用Macと会社Macで利用する非公開・単一ユーザーアプリとする。会社Macではビルド済みアプリバイナリの実行を優先し、直接配布が安定しない場合は会社Macでローカルビルドする。

## MVPに含める

- macOSのみを対象としたデスクトップアプリ。
- 私用MacでのReleaseビルドと会社Macへ渡せるアプリバイナリ生成。
- 原則として会社Macでソースコードや開発環境なしにアプリを起動できること。
- ユーザー操作による範囲キャプチャ。
- ユーザー操作による音声録音。
- ユーザー操作による画面録画。
- macOSメニューバーへの常駐。
- キャプチャ、音声録音、画面録画を開始するグローバルショートカット。
- 音声録音・画面録画の停止操作、経過時間、取得状態の表示。
- 録音開始前の選択中マイク名と短時間の入力レベル表示。未接続の前回選択マイクを別デバイスへ無断で切り替えない。
- 録音中のマイク音声・システム音声の別々のレベル表示と、無音・入力停止候補の警告。無音判定は自動停止に使わない。
- 保存中、AI処理中、完了、失敗の簡潔な状態表示。
- 画像、音声、動画の原本をローカル保存。
- 画像、PDF、テキストファイルとBacklog／Slack等の原文を一次Sourceとして手動取り込みする。
- 貼り付けたテキストだけでも一次Sourceとして登録できる。
- Input、Analysis、Outputを同じSourceとして保存し、単体・複数Source・Groupから来歴付きの派生Sourceを生成する。
- Analysis Sourceへテキスト、画像、URLを追加し、追加専用Revisionとして再分析できる。音声、動画、PDFは新規Sourceとして取り込む。
- 同じSourceを複数Groupへ関連付け、Group追加時には統合・出力を自動生成しない。
- Taskと複数Source／Groupを多対多で関連付ける。
- AIが問い合わせ、質問、MTG整理、要件定義書作成、議事録作成、見積もりなどのタスク分類候補を付与する。
- AI分類には主分類、タグ、確信度、理由、確認状態を保持し、ユーザー確認前は`proposed`とする。
- 取得時の前面アプリ名とBundle IDをManifestへ保存する。ウィンドウタイトルは自動保存しない。
- 現在の総コンテンツ数とLocal Vault使用量の表示。
- 音声・動画に含まれる会話の文字起こし。
- 取得直後のClaude Code分析。
- Claude Code分析でSonnet／Opusを選択し、既定値をSonnetとしてローカルに保持する。
- ユーザーが明示的に取得・取り込みしたSourceの保存後自動処理。
- AI解析中もInput取得を継続し、Sourceを解析Queueへ追加して順次処理する。
- アプリ終了・異常終了時に未処理または処理中だったSourceを、次回起動時に永続状態からQueueへ復元する。
- Claude Codeが5分以内に完了しない場合はプロセスを終了し、対象Sourceを再試行待ちへ隔離して後続Queueを継続する。
- 使用上限、認証切れ、タイムアウト、不正出力、一般実行失敗を分類して処理状態とProcessing Jobへ記録する。
- 自動処理に失敗したSourceの状態表示と手動再実行。
- 要約、事実、決定、対応、質問、リスク、返答待ちを含むMarkdown生成。
- 過去のSourceとの関連判定。
- 案件・タスク候補への自動グルーピング。
- 自動グルーピング候補の手動修正に必要なデータ保持。
- 保存、再分析、保護ロック解除と削除の明示操作。
- 新規・既存Sourceを既定で保護ロックし、「参照確認→一時ロック解除の確認→削除確認→macOSのゴミ箱へ移動」の順で行う復元可能な破棄操作。
- アプリ再起動後もSQLite Indexから直近Sourceを復元して破棄できること。
- 保存完了通知はユーザーが明示的に有効化した場合だけ表示する。
- 初期無効のSlack／Teams録音確認をローカルで提供する。前面20秒継続かつ未録音で、アプリ別cooldown中・当日抑制中でない場合にだけ候補表示する。
- 録音確認パネルは「録音開始」「15分後に通知」「今回は通知しない」「今日は通知しない」を提供し、自動録音は行わない。対象アプリ、継続時間、cooldownは設定で変更できる。

## 別スコープ

- 撮り溜めたコンテンツの一覧管理。
- 要約、文字起こし、グルーピングの詳細レビュー画面。
- ユーザーによる確認、修正、確定、保留、却下の操作体験。
- 最低1日1回のレビュー導線と通知。
- Sourceへの補足、複数Sourceの関連付け、解析目的を変えた再解析、AI結果の詳細確認。
- Analysis一覧の具体的要約・JST日時表示、Action管理、保護ロックの詳細UI。
- Transcript訂正と用語辞書のUI。生Transcriptの原本保持、訂正Source、辞書Revision、決定的補正は[Transcript訂正・用語辞書要件](transcript-correction-terminology.md)で設計する。
- Jira、Confluence、Backlogへの外部公開Adapter。AI生成後の本文・Project／Space・種別・添付の承認と、資格情報・重複作成防止を含めて別Phaseで設計する。
- タスク整理画面からの新規Input操作。

これらは必要な機能だが、常駐型Inputエージェントと同時に作り込まず、別のタスク整理インターフェースとして設計する。タスク整理画面にはキャプチャ・録音・録画・手動取り込みを配置しない。

## Sourceの対象

- Slack、Teams、メール、Backlog、Jira、Confluenceの画面。
- Figma、Excel、PowerPointなどの作業画面。
- Slack Huddle、Teams、対面会話などの音声。
- 操作や説明を含む画面録画。

## AI処理の状態

- `pending_analysis`: 原本保存済み、AI処理前。
- `completion_sync_pending`: Analysis SourceとSummaryは保存済みで、親Manifestの状態同期だけが未完了。起動時の復旧対象とし、5秒・30秒・5分の最大3回だけ自動再同期する。解析失敗として表示せず、再解析の対象にしない。
- `completion_sync_failed`: 自動再同期が3回失敗した状態。自動処理を停止し、診断表示と手動再同期を提供する。手動再同期でもAnalysisを再生成しない。
- `analysis_integrity_failed`: Analysis Sourceは存在するが、Revision、Summary snapshot、`operationId`、SHA-256の整合性を確認できない状態。自動再解析・上書き・削除を行わず、診断と手動レビューを要求する。
- `proposed`: AIによる要約・グルーピング候補を生成済み。
- `needs_review`: ユーザー確認待ち。
- `confirmed`: ユーザー確認済み。
- `corrected`: ユーザーが修正して確認済み。
- `deferred`: 保留。
- `rejected`: 不要または誤認として却下。

## MVPに含めない

- Windows対応。
- App Store配布、一般公開、不特定多数向けインストーラー配布。
- 複数ユーザー、アカウント、権限、課金。
- クラウドサービス、サーバー、クラウド同期。
- Jira、Confluence、Backlog、Slackへの自動投稿。外部公開はユーザー承認を必須とする将来設計であり、自動投稿しない。
- Excel、PowerPointの自動編集。
- 常時画面録画。
- ユーザーが許可していないSourceのAI送信。
- Slack Huddle／Teams会議の開始、他アプリのマイク利用、画面UI内容を精密に検知すること。
- 録音忘れ防止からの自動録音。
- クラウド同期。
- Microsoft 365 Copilot連携。会社テナント側のAPI・エージェント許可が必要なためMVPでは保留する。
- Whisperモデル自体の学習・fine-tuning。誤変換対策は訂正Sourceと用語辞書による用語ヒント・決定的補正で行う。
